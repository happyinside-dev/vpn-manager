# История изменений

Изменения Proxy Manager по версиям: новые версии находятся сверху. Внутри каждой
версии изменения разделены на добавления, изменения поведения и исправления.
Инструкции по установке и эксплуатации остаются в README и тематических документах.

**Текущая версия — 0.2.4.** История относится к комплекту
[`proxy-manager-bundle`](proxy-manager-bundle/), включая установщик, подписки и
Telegram-бота. Корневая Go-панель с SQLite — отдельная реализация.

Нумерация приведена к формату `MAJOR.MINOR.PATCH`: `0.x.0` обозначает новый этап
развития, последняя цифра — обновления внутри него. Старые обозначения сохранены
в [таблице соответствия](#соответствие-старых-и-новых-версий). Даты старых релизов
в исходных заметках не указаны, поэтому здесь они не восстанавливаются предположительно.

## 0.2.4 — Управление без общего отключения VPN

Текущее состояние репозитория после прежней версии `2.5.3`. В эту версию также
собраны изменения OpenWRT, маршрутизации и статистики, описанные ранее в отдельных
заметках без собственного номера релиза. Изменение репозитория само по себе
не обновляет установленный VPS.

### Добавлено

- Адресное управление пользователями Xray через `HandlerService`: добавление,
  включение, отключение, удаление и ротация UUID без перезапуска всего Xray.
- Отдельный локальный сервис авторизации Hysteria `proxy-manager-auth.service`.
  Актуальные пароли и состояние пользователей применяются через HTTP-авторизацию;
  `/kick` отключает сессии только целевого аккаунта.
- `upgrade-live-users.sh` для перехода существующей установки на новый режим
  с сохранением UUID, паролей, subscription tokens, Telegram-привязок и серверных ключей.
- Восстановление незавершённых операций через `pending-user` и
  `proxy-manager-recover.timer`; ошибочная операция откатывается для одного аккаунта.
- Статистика трафика в Telegram: по всем профилям для администратора и по своему
  профилю для пользователя, за всё время учёта и последние семь дней.
- Постоянное хранилище статистики `traffic.json`, опрос Xray и Hysteria раз в минуту,
  ручное обновление и отображение недоступности источников.
- Профили OpenWRT для отдельного sing-box: TUN, `auto_redirect`/fw4, локальные сети,
  multicast/IPTV и отдельный DNS-вход для интеграции с dnsmasq.
- Два выбираемых режима маршрутизации: **VPN, кроме РФ** (`bypass-ru`) и
  **Только заблокированные** (`blocked`). Устройство и режим закрепляются в URL,
  доступны через Telegram, Source, Import и QR.
- Статический бинарник `vpn-manager-live` для Linux amd64; скрипты обновления
  предпочитают его, если он присутствует.
- Проверки операций, отката, восстановления, конкурентных записей и сохранения
  соединений других пользователей на настоящих Xray и Hysteria.

### Изменено

- Обычные операции `account add|enable|disable|rotate|delete` больше не перезапускают
  Xray, Hysteria или backend подписок после включения нового режима.
- Backend подписок читает актуальный `users.yaml` при каждом запросе. Новый UUID,
  пароль или отзыв subscription token применяется без перезапуска backend.
- Конфигурация Xray проверяется и сохраняется атомарно для последующего независимого
  перезапуска демона, без перезапуска при каждом изменении аккаунта.
- Операции CLI и Telegram сериализуются общей блокировкой. Синхронизация подписок,
  привязка Telegram и ротация token используют общую блокировку записей `users.yaml`.
- Старые URL подписок без выбранного режима маршрутизации продолжают работать
  с прежними встроенными правилами.
- История релизов объединена в корневом `CHANGELOG.md`; нумерация проекта приведена
  к диапазону `0.0.0–0.2.4`.

### Исправлено

- Общий обрыв VPN при изменении одного аккаунта.
- Ложный успех при ошибке отдельного RPC Xray: проверяется число применённых
  операций, поскольку CLI может вернуть код завершения 0 при отказе API.
- Возможная потеря параллельных изменений token, Telegram-привязок и подписок.
- Кратковременная недоступность обновлённого `users.yaml` из-за установки прав
  и владельца после публикации файла: теперь они устанавливаются до замены.
- Навигация и обновление отчётов статистики в Telegram; статистика привязана
  к VPN-профилю, а не к Telegram ID.

### Обновление и ограничения

- Первое включение через `upgrade-live-users.sh` требует одного перезапуска Xray
  и Hysteria. Последующие операции с аккаунтами применяются без общего перерыва.
- Без настроенного нового режима изменения аккаунтов отклоняются с инструкцией
  обновиться; автоматического возврата к перезапуску VPN нет.
- `apply`, переустановка, смена серверных ключей и тестирование версий Xray
  по-прежнему могут перезапускать VPN.
- Удаление UUID из Xray запрещает новые подключения, но уже открытые VLESS-соединения
  могут сохраняться до закрытия. Для Hysteria реализован адресный `/kick`.
- Новые режимы маршрутизации загружают удалённые `.srs` через VPN: первый запуск
  зависит от доступности источников правил. Это отличается от прежних встроенных правил.
- Проверка настоящих демонов выполнена с Xray 26.6.27 и Hysteria 2.13.0:
  соединения другого пользователя продолжали передавать данные, PID процессов
  не менялись. Тестовый VLESS inbound работал без REALITY; генерируемая конфигурация
  REALITY отдельно проверялась через `xray run -test`. Проверки systemd на целевом
  VPS и реального интерфейса Telegram выполняются отдельно.

Подробности: [обновление и управление аккаунтами](proxy-manager-bundle/LIVE-USERS.md),
[статистика](proxy-manager-bundle/TRAFFIC.md),
[маршрутизация и OpenWRT](proxy-manager-bundle/ROUTING.md).

## 0.2.3 — Кнопка импорта в Telegram

Прежнее обозначение: `2.5.3`.

### Добавлено

- Кнопка **Импортировать** в сообщениях Telegram с профилями устройств.
- HTTPS-страница `/sub/<TOKEN>/<platform>?import=1` с явным переходом по
  `sing-box://import-remote-profile`. Это позволяет использовать обычную HTTPS-ссылку
  в кнопке Telegram и запускать импорт со страницы.

### Изменено

- Source, Import и QR сохранены; обновление не меняет VPN-секреты и subscription tokens.
- Для обновления бота и подписок доступен `upgrade-telegram-only.sh` без переустановки VPN.

Если встроенный браузер Telegram не открывает sing-box, страницу можно открыть
во внешнем браузере или добавить Source вручную.

## 0.2.2 — Интерфейс Telegram и стабильные операции аккаунтов

Прежнее обозначение: `2.5.2`.

### Добавлено

- Клавиатуры администратора и пользователя, выбор устройства и карточки аккаунтов.
- Действия из карточки: ссылки, приглашение, включение, отключение, ротация,
  удаление и отвязка Telegram. Для опасных действий предусмотрено подтверждение.
- Повторная выдача приглашений: новый код отменяет предыдущий для этого аккаунта,
  срок действия — десять минут. Код можно отправить в личный чат без `/start`.
- Меню платформ и команда `/platforms`; ссылки доступны в форматах QR, Source и Import.
- `upgrade-telegram-only.sh` с резервным копированием и откатом при ошибке.

### Исправлено

- Бот больше не перезапускает сам себя при вызванном из Telegram изменении аккаунта.
  При обычной синхронизации он запускается только если неактивен; при обновлении
  перезапускается один раз в конце.
- После добавления или удаления проверяется фактическое состояние аккаунта,
  чтобы корректно обрабатывать частично успешные операции.
- Групповые чаты отклоняются; роль и принадлежность профиля проверяются при каждом callback.

## 0.2.1 — Исправление синхронизации после добавления и удаления

Прежнее обозначение: `2.5.1`.

### Исправлено

- `backup_configs()` теперь успешно завершается при отсутствии необязательного
  `vpn-manager-telegram.service`. Раньше под `set -e` это прерывало синхронизацию
  подписок уже после создания или удаления аккаунта, и бот сообщал об ошибке,
  хотя сама операция с VPN была выполнена.

Код Go и настройки VPN-протоколов в этом обновлении не менялись.

## 0.2.0 — Управление через Telegram

Прежнее обозначение: `2.5.0`.

### Добавлено

- Необязательный Telegram-бот как отдельный процесс на том же бинарнике `vpn-manager`.
- Команды администратора для пользователей, создания и удаления аккаунтов,
  включения, отключения, ротации секретов, приглашений и проверки состояния сервера.
- Команды пользователя для своих ссылок, платформ, статуса и смены секретов.
- Привязка числового Telegram ID к VPN-профилю через одноразовое приглашение
  со сроком действия десять минут; поддержка нескольких администраторов.
- Раздельная ротация VPN-секретов (`/rotate`) и subscription token (`/rotate_token`).
  Первая сохраняет URL подписки; вторая отзывает прежние URL.
- Локальная генерация QR через `qrencode` и журнал аудита без записи секретов.

### Изменено

- Сервис подписок остаётся непривилегированным, бот выполняет операции управления
  от root через существующий shell-менеджер.
- Авторизация Telegram основана на числовых ID, а не username. Неизвестным
  пользователям не выдаются сведения о сервере или аккаунтах.
- Сохранено сетевое поведение предыдущей версии `0.1.1`.

В этой исторической версии изменения аккаунтов ещё перезапускали VPN, а смена
subscription token — backend подписок. Это изменено в `0.2.4`.

## 0.1.1 — Запуск Android и TV без предварительной загрузки правил

Прежнее обозначение: `2.4.6`.

### Изменено

- Критичные для первого запуска правила российских сервисов встроены в профили
  Android/TV как inline rule-sets. Для их запуска больше не требуется заранее
  загружать удалённые `.srs`.
- Сохранены прямые маршруты для `.ru`, `.su`, `.рф` и правила Android-приложений.
- Xray по умолчанию закреплён на `26.6.27`.
- Из матрицы совместимости исключены кандидаты `26.7.11+` для sing-box 1.14.x.

## 0.1.0 — Проверка совместимости Xray с откатом

Прежнее обозначение: `2.4.5`.

### Добавлено

- Команды `proxy-manager xray version`, `xray test VERSION` и `xray matrix`.
- Проверка кандидатов локальным VLESS/REALITY E2E-тестом с возвратом к предыдущей
  версии при неудаче.
- Сохранение первой прошедшей проверку версии в `/etc/proxy-manager/xray-version`.
  Установщик использует это закрепление, если явно не задан `XRAY_VERSION`.

Проверки не меняют UUID, пароли, REALITY-ключи, short ID или subscription tokens.
В этой версии матрица выбирала кандидатов до `26.9.8`; ограничения были уточнены
в `0.1.1`.

## 0.0.4 — Закрепление версии Xray

Прежнее обозначение: `2.4.4`.

### Добавлено

- Переменная `XRAY_VERSION` для явного выбора версии Xray.
- Проверка фактически установленной версии после установки.

### Изменено

- Xray по умолчанию закреплён на `26.3.27` для совместимости REALITY с sing-box 1.14.x.
- Используется официальный установщик XTLS с `--version` и `--force`.

Это историческое закрепление; значение по умолчанию изменено в `0.1.1`.

## 0.0.3 — Загрузка удалённых правил sing-box

Прежнее обозначение: `2.4.3`.

### Исправлено

- Удалённые rule-sets загружаются через отдельный HTTP-клиент `rules-direct`
  в sing-box 1.14+, направленный через `direct`.
- `route.default_http_client` и `http_client` каждого удалённого rule-set
  явно ссылаются на `rules-direct`; DNS загрузки использует `dns-bootstrap`.
- Устранена зависимость загрузки этих правил от ещё не запущенного VPN-маршрута.

Платформенные URL и прямые маршруты Android/TV сохранены. В `0.1.1` критичные
правила Android/TV были дополнительно перенесены в inline-конфигурацию.

## 0.0.2 — Исправление SNI-проверки Hysteria

Прежнее обозначение: `2.4.2`.

### Исправлено

- При `HY_INSECURE=1` конфигурация сервера Hysteria включает `tls.sniGuard: disable`.
  Внешний SNI больше не блокируется из-за несовпадения с именем сертификата VPS.
- Настройка сохраняется при повторной генерации конфигурации, `apply`,
  переустановке и изменениях аккаунтов.

## 0.0.1 — Независимый внешний SNI Hysteria

Прежнее обозначение: `2.4.1`.

### Добавлено

- Независимый `HY_SNI`: при `HY_INSECURE=1` он может указывать на внешний домен.
- Сохранение `server.hy_insecure` в state и передача настройки в профили подписок,
  Hysteria self-test и ссылки `hysteria2://` с `insecure=1`.

### Исправлено

- Внешний `HY_SNI` в insecure-режиме не обязан разрешаться в IP VPS.
- Сертификат Let's Encrypt запрашивается для домена Xray; домен Hysteria включается
  только при проверяемом TLS и принадлежности VPS.
- Флаг `-S` сохраняет секреты, позволяя явно переопределять SNI и TLS-политику.

## 0.0.0 — Базовый комплект подписок

Прежнее обозначение: `2.4` из общего `README.txt`; начальная точка истории.

### Добавлено

- Установщик Xray VLESS/REALITY и Hysteria 2, управление аккаунтами и backend подписок.
- Профили Universal, Android, iOS, macOS, Linux и TV/IPTV.
- Source/Import-ссылки, прямые маршруты российских сервисов и локальных сетей;
  Android/TV используют дополнительные правила по пакетам приложений.
- Обновление с `-S` для сохранения VPN-секретов; синхронизация подписок сохраняет
  существующие subscription tokens.

# Управление аккаунтами без общего отключения VPN

Изменения относятся к `proxy-manager-v2.5.3-bundle`. Корневой Go-проект с SQLite
остаётся отдельной реализацией; переноса аккаунтов между двумя проектами нет.

После обновления команды `proxy-manager account add|enable|disable|rotate|delete`
и соответствующие действия Telegram не перезапускают Xray, Hysteria или backend
подписок. При переходе сохраняются UUID, пароли, subscription tokens, привязки
Telegram, REALITY-ключи и сертификаты.

## Обновление существующего сервера

Скопируйте обновлённый bundle целиком. Для Linux amd64 подготовлен новый статический
бинарник `vpn-manager-live`; прежний `vpn-manager` оставлен на месте. Скрипты
предпочитают новый бинарник, если он присутствует.

Для самостоятельной сборки (Go 1.23+):

```bash
cd proxy-manager-v2.5.3-bundle/src
CGO_ENABLED=0 go build -trimpath -o ../vpn-manager-live ./cmd/vpn-manager
cd ..
```

На сервере с установленным bundle и подписками:

```bash
sudo bash upgrade-live-users.sh
```

**Первое включение требует одного перезапуска Xray и Hysteria:** нужно включить
HandlerService и заменить статическую авторизацию Hysteria. Следующие изменения
аккаунтов применяются без перезапусков. Upgrade обновляет также backend подписок,
бота и wrapper. Полный установщик и смену серверных ключей он не запускает.

Резервные копии: `/var/backups/proxy-setup/`. Если переход конфигураций не удаётся,
команда включения восстанавливает прежние конфигурации VPN и запускает их снова.
Обновление Telegram/backend имеет отдельный откат в `upgrade-telegram-only.sh`.

Для новой установки обновлённый `install-with-subscriptions.sh` включает режим
автоматически после установки backend.

## Применение изменений

* Xray: HandlerService, inbound tag `vless-reality`, адресные `api rmu` / `api adu`.
  Проверяется число успешных операций: CLI Xray иногда возвращает exit code 0
  даже при ошибке отдельного RPC.
* Hysteria: отдельный `proxy-manager-auth.service` на **127.0.0.1:18081**.
  Он читает атомарно обновляемый `/etc/hysteria/auth-users.json` при каждом новом
  подключении. В snapshot только имена и пароли активных аккаунтов и sentinel;
  REALITY private key в нём нет.
* После обновления авторизации Hysteria `/kick` отключает только целевой аккаунт.
  При ротации его клиент должен обновить профиль и переподключиться.
* Backend подписок читает `users.yaml` при каждом запросе: новые UUID/пароли и
  отзыв token применяются сразу. Telegram не перезапускает backend ради token.
* Xray config сохраняется атомарно с проверкой `xray run -test`, без перезапуска.
  Независимый перезапуск Xray загружает актуальные сохранённые аккаунты.

Порты 10085, 10086 и 18081 остаются только на loopback. Не проксируйте авторизацию
Hysteria в публичный интернет. Авторизация отделена от подписок и Telegram,
поэтому перезапуск этих компонентов не останавливает её.

## Ошибки и ограничения

CLI/Telegram сериализуются блокировкой `accounts.lock`. Все записи `users.yaml`
используют общую файловую блокировку, чтобы sync, Telegram-привязки и ротация token
не теряли изменения друг друга. Права и владелец временного файла устанавливаются
до его публикации.

При ошибке менеджер возвращает прежнее состояние и повторно применяет его только
для целевого пользователя. `pending-user` отмечает незавершённую операцию.
`proxy-manager-recover.timer` каждые 30 секунд повторяет её из сохранённого state;
до восстановления следующая операция не выполняется. Это исправляет в том числе
UUID после прерывания между записью state и обращением к Xray. Пустой таймер не
меняет пользователей и не создаёт пустые логи.

Без настроенного live-режима изменения аккаунтов отклоняются с инструкцией
обновиться; скрытого fallback на перезапуск VPN нет.

`proxy-manager apply`, переустановка, смена серверных ключей и тестирование версий
Xray по-прежнему могут перезапускать VPN — это серверные операции.

Удаление пользователя из Xray запрещает новые подключения с его UUID; уже открытые
VLESS-соединения могут продолжить работу до закрытия. Немедленный разрыв всех
VLESS-сессий заблокированного аккаунта здесь не реализован. Для Hysteria есть `/kick`.

## Проверки

```bash
cd src
go test -race ./...
go vet ./...
cd ..
bash tests/live-users.sh
```

Shell-тест проверяет операции, откат при RPC-ошибке с exit code 0 и восстановление
после сбоя. Вызов перезапуска сервиса приводит к ошибке теста.

Необязательная проверка настоящих процессов: свободные TCP-порты loopback
10085, 10086, 18081; Python 3, openssl, jq, curl, bash:

```bash
python3 tests/live-runtime.py /path/to/xray /path/to/hysteria ./vpn-manager-live
```

Проверено с Xray 26.6.27 и Hysteria 2.13.0: постоянные VLESS и Hysteria-соединения
Bob передают данные во время ротации, отключения, включения, добавления и удаления
других аккаунтов, PID процессов сохраняются. VLESS в тесте использует локальный TCP
inbound без REALITY: проверяются runtime-пользователи и сохранение соединений.
Генерируемая конфигурация REALITY отдельно проходит `xray run -test`.

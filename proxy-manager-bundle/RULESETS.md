# Управление правилами маршрутизации

Изменения относятся к модулю `src` (бинарник `vpn-manager`). Корневой Go-модуль,
его SQLite, API администратора и авторизация не изменены.

## Найденная архитектура

- `src/internal/profile/generator.go`: JSON Sing-box, Hysteria2, VLESS Reality,
  selector/urltest, DNS, TUN, Android package rules и оба режима маршрутизации.
- `src/internal/subscription/service.go`: проверка пользователя по токену,
  получение конфигурации сервера, вызов генератора.
- `src/internal/httpserver/server.go`: `/sub/{token}` и варианты платформ/режимов.
  Устройство выбирается суффиксом URL, а не User-Agent. Старые URL сохраняются.
- `src/internal/importurl`, CLI `links`, Telegram bot: URL подписок и импорта.
- `src/internal/server/provider.go`, `users`: существующие YAML-конфигурации и
  снимки пользователей; интеграция с состоянием proxy-manager сохранена.
- `src/cmd/vpn-manager/main.go`: HTTP и graceful shutdown, JSON-логи slog.
  Telegram имеет собственный минутный ticker; корневой backend — reconciliation
  Xray каждые 30 секунд. Менеджер правил работает в процессе подписок отдельно.
- Базовая проверенная версия клиента в ROUTING.md — Sing-box 1.14.4.
  Новые правила используют inline (доступно с 1.10), но это не означает совместимость
  всей существующей конфигурации с 1.10. Версии ниже 1.14.4 здесь не проверялись.

## Поведение

Клиент получает полный проверенный набор правил внутри JSON (`type: inline`).
`http_clients`, удалённые rule-set и GitHub URL из генерируемых конфигураций удалены.
Подписку следует обновить в клиенте один раз после обновления сервера.
Дальнейшие обновления списков приходят при обновлении подписки, а не раз в сутки
самим клиентом. Цена независимого запуска — увеличение размера JSON и памяти.

- `bypass-ru`: российские домены, приложения и `geoip-ru` напрямую;
  `route.final = proxy`.
- `blocked`: `ru-blocked` и `ru-blocked-ip` через VPN; `route.final = direct`.
- Старые URL без режима сохраняют прежнюю политику встроенных российских доменов.
- При первом запуске без полного снимка явные режимы отвечают HTTP 503.
  Неполные/пустые списки не подставляются. Уже импортированные профили продолжают
  работать без обращения к серверу правил.

## Настройка

1. Установить доверенный Sing-box 1.14.4 на сервер подписок. Он используется
   только как локальный валидатор/декодер (`rule-set decompile`), без запуска TUN.
2. Скопировать `rules.example.json` в `/etc/vpn-manager/rules.json`, заменить
   **все** example URL реальными HTTPS-источниками своей инфраструктуры или
   проверенными upstream. Имена ключей фиксированы. Можно задать `sha256`
   (64 шестнадцатеричных символа в нижнем регистре); при закреплении хеша его
   нужно менять вместе с обновлением источника. Upstream доступны только серверу.
3. Пересобрать `src/cmd/vpn-manager` и установить бинарник существующим способом.
   Обновить systemd unit из install-with-subscriptions.sh: `StateDirectory=vpn-manager`
   разрешает запись при `ProtectSystem=strict`. Для ручной установки создать
   `/var/lib/vpn-manager` с владельцем пользователя службы и разрешить запись в unit.
4. Перезапустить подписки и проверить журналы: `rule-set snapshot updated`.
   Загрузка запускается сразу, затем через 24 часа; после ошибки повтор через
   5 минут. Правки rules.json применяются после перезапуска.
5. Проверить HTTPS API:
   `/sub/rules/files/geoip-ru/file.srs`,
   `/sub/rules/files/ru-blocked/file.srs`,
   `/sub/rules/files/ru-blocked-ip/file.srs`.
   Эти публичные несекретные списки проходят через существующий nginx `/sub/`;
   TLS завершается там же, где TLS подписок. Backend остаётся на loopback.
   API поддерживает HEAD, ETag, условный GET и диапазоны байтов.

Флаги службы: `-rules-config`, `-rules-dir`, `-sing-box`.
Для офлайн-установки перенести весь каталог rules с проверенным снимком
с подготовленного сервера, сохранив относительную ссылку `current` и владельца.

## Хранение и отказоустойчивость

Каждая `generation-*` содержит три настоящих `.srs` и `snapshot.json` с бинарными
копиями, SHA-256 и декодированными правилами. После записи и fsync всего поколения
атомарно переключается ссылка `current`, затем синхронизируется родительский каталог.
HTTP и генератор читают неизменяемый снимок в памяти; одна подписка получает оба
blocked-списка из одного поколения. Сохраняются текущее и предыдущее поколения для ручного отката; более старые
каталоги очищаются после успешного обновления. Неизменившиеся списки не создают
новое поколение. Для длительной истории нужны отдельные резервные копии. Менеджер рассчитан на один процесс
обновления для одного каталога.

Загрузчик ограничивает файл 64 MiB, декодированный JSON 64 MiB, HTTP 90 сек,
валидатор 30 сек; запрещает HTTP и понижение HTTPS при редиректе. Проверяются
HTTP 200, SRS magic, полноценное декодирование, непустой список и необязательный
закреплённый SHA-256. Локальный снимок повторно проверяется при старте. Любая ошибка
обновления оставляет прошлый снимок; ошибка локального снимка явно останавливает
запуск службы вместо незаметной смены политики. Проверка формата не доказывает
актуальность или достоверность содержимого upstream: это ответственность выбранного
источника и закреплённого хеша.

## Остальные зависимости

DNS Cloudflare (1.1.1.1), DNS Яндекса (77.88.8.8), системный DNS для bootstrap и
Cloudflare generate_204 для urltest остаются внешними зависимостями. Они могут
нарушать резолвинг и автоматический выбор протокола. TLS требует исправного
сертификата и продления ACME; Reality — доступности выбранной цели/SNI.
Telegram нужен для управления через бота, но не для работы импортированного профиля.
Установочные скрипты всё ещё используют внешние пакеты/релизы. Эта задача не меняет
протоколы и DNS, но устраняет внешнюю загрузку правил на пути запуска клиента.

## Проверки

В `src`: `go test -race ./...`, `go vet ./...`.
При наличии Sing-box тесты реально компилируют/декодируют SRS и выполняют
`sing-box check` для всех платформ и режимов. Без бинарника эти интеграционные
проверки пропускаются. Unit-тесты проверяют политики маршрутизации, отсутствие
удалённых списков, 404/повреждения/checksum, сохранение прошлого поколения,
офлайн-перезапуск, API и ETag.

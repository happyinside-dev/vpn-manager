# Разрешения Telegram-бота

Главный администратор (`masters` в конфигурации бота) открывает «Пользователи», выбирает профиль и выдаёт или отзывает два независимых разрешения:

- **Секреты** — смена собственных VPN-секретов и токена подписки.
- **Управление** — создание профилей и управление только теми профилями, которые создал этот Telegram-пользователь: ссылки, статистика, приглашения, отвязка Telegram, включение, отключение, смена секретов и токена, удаление.

Можно использовать команды `/permissions NAME rotate on|off` и `/permissions NAME manage on|off`.

По умолчанию оба разрешения выключены, в том числе у существующих профилей. Главные администраторы сохраняют полный доступ. Пользователю с правом управления доступны кнопки «Пользователи» и «Создать профиль»; после изменения прав следует открыть «Меню». Отзыв прав действует сразу для команд, старых кнопок и незавершённого ввода имени.

В главном меню администратора показаны группы «создатель → созданные профили». В списке пользователей у каждого профиля указан создатель. Для ранее созданных профилей происхождение неизвестно: они попадают в группу «Администратор / ранее созданные».

Права и числовой Telegram ID создателя сохраняются в `users.yaml` (`can_rotate`, `can_manage_users`, `created_by`). Синхронизация учётных записей сохраняет эти поля. Владение связано с Telegram ID создателя, не с именем профиля; передача привязки профиля другому Telegram-аккаунту не передаёт ранее созданные профили.

Изменения относятся к боту из `proxy-manager-bundle/src`. В комплект включён готовый бинарник для Linux x86_64; Go на сервере не требуется. После загрузки обновлённого комплекта запустите из его каталога:

```bash
sudo bash ./upgrade-telegram-only.sh
```

Скрипт проверит запуск бинарника, сохранит резервную копию, обновит бинарник и помощник синхронизации и перезапустит включённую службу Telegram-бота. При ошибке установки он восстановит прежний бинарник и помощник синхронизации. Данные старого формата читаются без ручной миграции.
